·# Markdown effort-page coverage audit

Date: 2026-10-02. Editable population backlog, not a data migration.

## Scope and method

Scanned all **888 Markdown files under `markdown/`**: 728 collections, 87 canvas, 53 efforts, 14 feeds, and 6 dashboards. The application source parser recognizes **2,301 workout blocks in 737 files**, yielding **9,223 effort-bearing statements, 600 distinct labels, and 576 generated slugs**. Repeated statements count separately, not once per executed round. Prose mentions, equipment tags, query filters, and repository documentation outside `markdown/` are not movement occurrences. The existing new-note template is outside this corpus.

Used the current source `parseDocumentSections` and `parseScript`, with the same default effort extraction used by seed compilation. The installed package parser produced identical effort rows. No thrown parse errors occurred; that does not mean the labels are semantically valid. This parser accepts malformed text and group labels as efforts.

Flash 5.3 was requested, but the available model interface rejected that identifier and only accepts `default`, `smol`, or `slow`. No substitute research model was used. Extraction and grouping were performed directly from repository sources. Proposed canonical names and semantic grouping are editorial recommendations, not existing registry facts.

## Findings

- **107 proposed movement-page rows**, including 4 alias splits/reassignments. These are planning groups, not a mandate to create 107 independent records. The notes identify rows that can reuse a neutral parent or need a variant decision.
- **39 existing effort pages referenced by grouped movements**, plus **14 existing pages without observed movement references after proposed regrouping**. All 53 existing effort documents are accounted for.
- **17 correction/classification rows** cover headings, instructions, placeholders, malformed syntax, and climbing parsing. Do not populate these parsed fragments as exercise pages.
- Only **775 of 9,223 generated statement slugs** exactly equal an existing effort slug; **8,448 do not**. This raw count includes non-movement labels. Exact page-slug coverage is intentionally stricter than fuzzy analytics resolution.
- **51 of 53 effort documents are metadata-only**. Only `burpee` and `kettlebell-swing` contain body text. A routable record and a useful explanatory page are separate population tasks.

## Lookup rules that affect population

[Effort page loading](../../apps/playground/app/hooks/useEffortContent.ts#L64) calls `registry.resolve(slug)`. [Registry resolution](../../packages/lang/src/effort-registry/CompositeEffortRegistry.ts#L65) uses an exact slug map. [Block-effort extraction](../../apps/playground/src/services/storage/StorageService.ts#L37) prefers `exerciseId`, otherwise lowercases effort text and replaces non-alphanumeric runs with hyphens. [Seed compilation](../../scripts/generate-seed.ts#L43) uses those same parsing/extraction functions.

[Analytics resolution](../../packages/lang/src/effort-registry/EffortResolver.ts#L44) also supports aliases and fuzzy matches, then a synthetic fallback. That fallback is not a persisted effort page. **Adding aliases alone does not make an alias-derived slug resolve through the exact page lookup.** Population needs canonical exercise IDs or canonical slug association in the relevant indexing/linking path, in addition to aliases. Preserve original display wording where appropriate.

The [effort document format](../../apps/playground/src/repositories/effort-markdown.ts#L4) supports `id`, `slug`, `label`, `aliases`, `baseAttributes`, and a Markdown body. Populate a stable unique ID, canonical slug and label, observed true aliases, justified MET/discipline/intensity attributes, and useful body content. Do not invent MET values from this inventory. Equipment, side, tempo, distance, intensity, and movement variants must not be lost during grouping.
