1. Baseline findings and requested fixes

The crosswalk in section 2 incorporates the published query and route changes. Imported-note isolation now covers efforts and equipment as well as collections and dashboards. Sections 3–6 preserve the original audit for comparison. Analytics scoping and category joins are separate findings, not additional requests in this annotation bundle.

Imported-note isolation

Fix journal leakage across imported kinds
Imported notes now receive corpus sourceId values. The seed schema repair updates existing imports, including user-edited seeds, without replacing their content. Journal queries reject legacy corpus provenance as well as explicit non-journal sources. Verified in the browser: the previously leaking journal query now returns only the user journal note.

Analytics Scope Divergence

All Runtimes Aggregated
QueryService.run() scans raw EventRecord rows without checking parent note type or source. Playground runs and home page test runs pollute analytical volume/load queries.

Seeding Type Flatness

Hardcoded type: 'note'
SeedImporter.ts:rowToRecords ignores frontmatter type: and assigns type: 'note' to collection READMEs, dashboards, and efforts.

WQL Grammar Boundary

Target & Head Fences
WQL find targets are closed to note, block, effort, session, segment, event. Concepts like :dashboard or :category fail parse-time validation.

3. Validation of Content Statements

This section preserves the pre-feedback audit for comparison. Its statuses describe the original implementation, not the accepted crosswalk above.

Statement 1: "pages | collections (the top level readme per director becomes a note type category and should have a linl table of notes that are part of the collection.)"

Status: Partially Implemented with Architectural Mismatches

  • UI Routing Layer: apps/playground/app/canvas/canvasRoutes.ts correctly matches markdown/collections/([^/]+)/README.md and constructs a CanvasRoute at /c/:slug. When navigated, CanvasProsePanel.tsx embeds <CollectionWorkoutsList>, which renders the interactive table of member workouts.
  • Database Seeding Mismatch: SeedImporter.ts:rowToRecords ignores frontmatter type: or collection role. Every imported file (including README.md) is saved as Note.type = 'note'. There is no note typed as category in storage.
  • WQL Capability Mismatch: WQL has no :category target head, nor does it possess relational join expansion to return a collection header plus its member note records in a single query.
Statement 2: "collection a type of note that has a link toa collection should show up in collections but not on jorunal."

Status: Broken in Current Code (The Inversion Bug)

  • The Seeding Flaw: SeedImporter.ts populates note.catalog = catalogForChunkId(chunkId) (e.g. 'crossfit-girls'), but leaves note.sourceId undefined.
  • The QueryService Bug: In packages/wql/src/QueryService.ts:sourceMatches(): 
    if (kind === 'journal') {
  ...
  return !sourceId || sourceId === 'journal'; // Matches because sourceId is undefined!
}
if (kind === 'collection' || kind === 'collections') {
  return !!sourceId && (sourceId.startsWith('collection:') || sourceId.startsWith('page:collection:')); // Fails!
}
  • The Consequence: Collection workout notes fail sourceMatches(n, 'collections') and evaluate to true for sourceMatches(n, 'journal'). They only stay hidden from the journal if their date falls outside the 4-week window. In runFindCatalog(), an ad-hoc fallback (n.catalog && !n.sourceId) was patched in to rescue catalog grouping.
Statement 3: "jouranl those are notes a user creates, they are their notes and should show up on journal not other imported notes."

Status: False in WQL Engine (Intent Correct, Execution Leaking)

  • User-Created Notes: Notes created via journalNotes.create (such as through CreateJournalNoteDialog.tsx) are saved with type: 'journal' and targetDate = Date.now().
  • Imported Notes: Notes from the seed importer carry seedOrigin: 'seed' and type: 'note'.
  • The WQL Gap: The :journal query head normalizes to target: 'note', filters: [source: 'journal']. It filters by source, not by seedOrigin or type: journal. Because imported notes carry sourceId: undefined, WQL cannot distinguish user-authored journal notes from imported corpus notes.
Statement 4: "playground all all the runtimes run by the stample pages the playground page or the home page, and are tracked but note part of the jorunal. analytics are done on the journal only)"

Status: Notes Isolated, Analytics Leaking Across All Stores

  • Note Isolation (Working): Playground notes are saved with type: 'playground' and sourceId: 'playground'. sourceMatches(n, 'journal') explicitly guards against item.type === 'playground' and item.sourceId === 'playground'. They do not appear on /journal.
  • Analytics Leak (Broken): When an aggregate query like sum:totalVolume{} or sum:tis{} by {week} runs, QueryService.run() invokes this.store.getEventsByTimeRange() or this.store.scanAll() over the entire eventStore.
  • Root Cause in Event Storage: EventRecord rows logged from runtime workouts carry noteId, resultId, and metric telemetry, but contain no source or noteType column. Furthermore, source is classified as a content-only filter (WQL_CONTENT_ONLY_KEYS) and is forbidden inside aggregate query braces. Analytics cannot isolate journal notes unless executed as a cross-store join (sum:totalVolume{} where find:note{source:journal}) or pipeline.
Statement 5: "efforts are a type of note"

Status: Dual Physical Representation / Architectural Fork

  • In Storage: Files in markdown/efforts/**/*.md are compiled into the seed and saved by SeedImporter.ts as Note rows (type: 'note') in noteStore.
  • In Domain Registry: The same files are parsed by parseEffortFile and saved as IEffort domain objects into IndexedDB's efforts store.
  • In WQL: The :effort query head does not query noteStore. It targets target: 'effort', executing QueryService.runFindEffort() directly over the effortsStore. Filtering notes with :note{type:effort} matches 0 records because effort notes in storage have type: 'note'.
Statement 6: "dashboards are a type of note"

Status: Storage True, WQL Engine False

  • In Storage: Vault dashboards created via dashboardNotes.createDashboard() are created using journal.create({ title, rawContent, type: 'note' }). Frontmatter contains dashboard: true. Prebuilt dashboards in markdown/dashboards/*.md are also seeded as type: 'note'.
  • In Discovery: useDashboards.ts must fetch every note in the database via notePersistence.listNotes({}) and parse raw YAML frontmatter in JS looking for meta['dashboard'] === 'true'.
  • In WQL: WQL has no :dashboard target or head in WQL_FIND_TARGETS. Searching :note{type:dashboard} returns 0 results because Note.type is hardcoded to 'note'.

4. Baseline seeding and note creation lifecycle

The following matrix records pre-feedback metadata. The attribution fix changes imported source IDs and dashboard note types; the original values remain here to explain the leak.

Corpus Partition in scripts/generate-seed.ts

The compiler scans markdown/ and chunks rows deterministically via chunkIdFor(relPath):

  • markdown/canvas/** → Chunk 'canvas' (home, guides, presets)
  • markdown/collections/<slug>/** → Chunk 'collection.<slug>' (workout cards & READMEs)
  • markdown/dashboards/** → Chunk 'dashboards' (prebuilt analytics dashboards)
  • markdown/efforts/** → Chunk 'efforts' (exercise registry definitions)
  • markdown/feeds/<slug>/** → Chunk 'feed.<slug>' (dated workout releases)
  • Derived: block-index.<n> & block-efforts.<n> → Precomputed block index and containment rows.

Runtime Ingestion in SeedImporter.ts

When chunks are fetched into IndexedDB storage:

  • Note ID: Stable RFC-4122 UUIDv5 derived from SEED_NAMESPACE:path.
  • Note.type: Hardcoded to 'note' across all note chunks.
  • Note.catalog: Set to chunk slug for collections/feeds; undefined for canvas, efforts, dashboards.
  • Note.sourceId: Never set (undefined).
  • Note.seedOrigin: Set to 'seed'. User edits set this to 'user' or leave it untouched.
  • Derived Rows: Precomputed block_index rows do carry sourceId: 'collection:<dir>', but the parent Note record does not.

6. Architectural Remediation & Unification Roadmap

The published feedback requests note attribution, query defaults, result routing, the inclusive All view, and dashboard note search. Category joins and analytics scoping remain separate audit recommendations.

Step 1: Fix Seeding Attribution in SeedImporter.ts

In apps/playground/src/services/seed/SeedImporter.ts:rowToRecords():

  • Dashboard corpus notes use type: 'dashboard'. Other imported types remain unchanged. Category typing and README joins are separate audit recommendations.
  • seedNoteSourceId() assigns the actual corpus family: 
    collections → collection:<catalog>[/<file>]
feeds       → feed:feeds/<directory>/<date>/<file>
canvas      → guides:<route-or-canvas-path>
dashboards  → dashboards
efforts     → efforts
template    → playground
  • Seed schema 7 repairs stored notes even when chunk hashes are unchanged. User-owned seed notes receive source metadata repairs without changing their title, content, or provenance. Unknown corpus chunks fail instead of importing sourceless notes. This corpus has no equipment directory; effort definitions carry equipment tags.

Step 2: Harmonize Note Creation in dashboardNotes.ts & Dialogs

  • In dashboardNotes.ts, create dashboards with type: 'dashboard' instead of type: 'note'.
  • In useDashboards.ts, replace the full-vault note scan with notePersistence.listNotes({ kind: 'dashboard' }).
  • In CreateJournalNoteDialog.tsx, when creating in collection mode, set sourceId: 'collection:<slug>'.

Step 3: Expand WQL Vocabulary in packages/wql/src/vocabulary.ts

  • Keep dashboard queries on the existing note target. A new find target is unnecessary; :dashboard {} injects type:dashboard.
  • Add :dashboard to WQL_SOURCE_HEADS mapped to target: note, type: dashboard.
  • Dashboard notes retain the existing tag and frontmatter model. Category and origin vocabulary expansion is outside this annotation bundle.

Step 4: Strict Journal & Analytics Scoping in QueryService.ts

  • Update sourceMatches(item, 'journal') to require item.type === 'journal' || item.sourceId === 'journal' and reject anything with seedOrigin === 'seed' or non-journal catalog.
  • In EventRecord or during fact projection, tag facts with source: 'journal' | 'playground' or default analytics queries to join find:note{source:journal} when no explicit source is supplied.

Step 5: Stream Profile & Route Configuration

  • Use :catalog{} by {tag} for catalogs, :collection {} last 2w for feeds, :session {} last 1d for sessions, and :playground{} by {date} last 1w for playgrounds. WQL places grouping before the time window. Session details use /results/:sessionId.
  • All uses :note{!source:playground} on an existing stream surface, with no /library path. Removing the exclusion includes playground notes. Palette searches use :note{source:journal,collection} by {date}. Dashboard discovery uses :dashboard {} with normal note tags and frontmatter.
