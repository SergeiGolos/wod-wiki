Dogfood Findings — Suggested Solutions

wod.wiki home page and core flows · dogfood session 2026-10-07 · desktop 1920px + mobile 390×844

Source report: dogfood session with the home page (7 findings: 0 critical, 2 high, 3 medium, 2 low). This document proposes one fix direction per finding, grounded in the current codebase where possible.

1. Note page forces horizontal overflow on phones

HighVisual Any /notes/<uuid> on a 390px viewport lays out at 401–420px: prose clips mid-word, the properties table and ```time block button groups overflow, and in the running clock the NEXT button and Session chip sit half off-screen.

Root cause

CodeMirror's .cm-content.cm-lineWrapping reports a 400px width with min-width: auto and no ancestor constrains it to the container; every child (properties table, fence blocks, clock overlay) inherits the 400px line box. Desktop is unaffected because the canvas is wide.

Suggested fix

  • Constrain the editor chain: min-w-0 / max-w-full on every wrapper between the page root and the CodeMirror EditorView, so .cm-content shrinks to the 390px viewport.
  • Below ~480px, stack the properties table into label/value rows instead of a two-column grid.
  • Move ```time block actions (Run / Playground / copy) into a full-width bar or an inline ⋯ menu.
  • Give the clock overlay its own snap-to-viewport layout: fluid clamp() digit sizing, controls in a 3-up grid capped at 100vw, Session chip inline rather than pinned to the expanded right edge. The overlay currently inherits the widened page viewport, which is what pushes NEXT off-screen.

One change restores readable notes and fully visible timer controls on phones — the core loop the app is built around.

2. Fresh profile: /journal dead-ends at "0 of 0"

HighFunctional On a fresh profile, navigating directly to /journal runs the journal query before seed import finishes ([seedSync] outcome: busy) and renders 0 of 0 · No entries match your search · Remove time window (last 4w) — no loading indicator, no re-query when seeding completes. Home-first navigation works (88–108 entries), so the query itself is fine; the timing is not.

Suggested fix

  • Introduce a vault-readiness gate in apps/playground/app/App.tsx: GlobalState already kicks off runSeedSync(); expose its outcome (busy | fresh | current | error, logged today at apps/playground/src/services/seed/seedSync.ts:74) through the existing seed-content context.
  • Routes that query the vault (journal, notes, canvas) render a skeleton while the outcome is busy, then mount normally. The empty state in QueriableStreamView.tsx only renders after the vault is confirmed ready — so "0 of 0" always means "no matches", never "still seeding".
  • No polling: the seed broadcast channel (SEED_BROADCAST_CHANNEL in seedSync.ts) already invalidates seed-content consumers; the journal's query subscribes to the same signal.

3. Seeding race flashes "library's routed content failed to load"

MediumUX On first run, tapping navigation while the seed import is still running can render the full-page RootUnavailable error (App.tsx:106-118) with a "Re-seed library" button. It self-heals once seeding finishes, but it is a frightening first screen and invites an unnecessary destructive-ish action.

Suggested fix

  • Reserve the error boundary for confirmed seed failure: only render RootUnavailable with the re-seed button when the seed outcome is error, or when it resolves current/fresh and the root page is still missing.
  • While the outcome is busy, keep the existing Loading library… route — regardless of which navigation control was tapped. The gate at issue #2 is the same gate; implement once.
  • Re-seed only appears after seeding has genuinely finished without a root page, which is the only situation where re-running the import can help.

4. Command palette rejects plain text, shows unfiltered list

MediumUX The palette defaults to WQL mode (:journal scope). Typing front squat shows a red Invalid — Cannot parse "front squat". Expected agg:metric{filters} by {dims}.rollup(period) while the list below still shows the unfiltered default set — an error message and no visible filtering. Text search requires discovering the text: prefix or the find chip, neither explained in the palette.

Suggested fix

  • Make plain text the default mode: when input parses as WQL, run WQL; otherwise treat it as a text search (auto-prefix text: internally) instead of showing a parse error.
  • Surface the active mode as a chip the user can flip (Find / WQL), so the dialect is an explicit choice, not a hidden convention.
  • Add a one-line syntax hint under the input that updates with the mode: e.g. Find: plain words match titles, tags, and bodies vs WQL: agg:metric by dims.
  • Only show the red Invalid state when the user has explicitly chosen WQL mode and the query still fails to parse.

5. Mobile parity: dense desktop paradigms shrink instead of reflow

MediumUX Three-pane workspaces (journal: WQL bar + facet columns + group-by + list; note: properties table + editor + per-block actions) are compressed on mobile rather than re-imagined: facets collapse behind a 24px sliders icon with no visible applied state, the WQL pill floats over list content, note titles truncate heavily, and the search FAB overlaps text. Everything is reachable, but density and discoverability are far below desktop.

Suggested fix — re-imagine, don't shrink

  • Journal facets become a full-screen modal sheet with applied-filter chips and a clear-all action, opened from the sliders icon.
  • Group-by becomes a segmented control instead of a panel.
  • Note properties become stacked label/value rows (same change as finding 1).
  • "On this page" TOC moves into the drawer with section anchors — one tap deeper at most, per the goal that every desktop capability stays within one tap.

Sequencing: land finding 1 first to establish the reflow pattern, then apply the same thinking route by route.

6. Floating search button overlaps content

LowVisual The round search FAB sits over note body text and the tag row with no scrim or auto-hide, and appears inconsistently (present on home/notes, absent from journal chrome).

Suggested fix

  • Auto-hide the FAB on downward scroll, reveal on upward scroll — standard mobile pattern, avoids covering readable text.
  • Anchor the search entry point in the bottom bar consistently across routes (home, journal, notes) instead of a floating duplicate.

7. One 404 resource and noisy seed-sync logs

LowConsole Every load logs one Failed to load resource: 404 (orphaned asset reference) and repeated [seedSync] outcome: busy info lines.

Suggested fix

  • Find the orphaned reference: reproduce with the Network panel open, fix or delete the asset.
  • Demote [seedSync] outcome: busy to console.debug (or drop the line) once the readiness gate from findings 2–3 exists — the UI no longer needs log archaeology to know seeding is in flight.

Cross-cutting note

Findings 2, 3, and 7 all touch the same boot path: App.tsx GlobalState → seedSync.ts → seed-content broadcast → vault-querying routes. One small "vault readiness" context solves the dead-end journal, the flashing error boundary, and most of the log noise in a single change. That is the recommended first PR, alongside the note-page min-width fix from finding 1.
