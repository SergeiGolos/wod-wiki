1. Query Kinds & High-Level Syntax

WQL exposes two query kinds — things or numbers — lexed through a single Lezer head grammar and mapped to typed ASTs by wql.ts:

find:<noun>

Things — Content, Sessions & Tables

Discovers authored documents, sessions, and cross-workout tables.

find:note{domain:crossfit, equipment:barbell} last 8w
find:block{effort:pull-up} | limit 20
find:effort{discipline:strength}
find:session{} last 4w
find:session{result:r1, plane:segment}
find:segment{effort:snatch} last 12w | select date, effort, totalVolume
Nouns (WQL_FIND_TARGETS): note | block | effort | session | segment | event
Returns: FindQueryResult { notes[], blocks[], efforts[], runs?, table?, stages }
<agg>:<metric>

Numbers — Analytics & Aggregates

Computes performance series and stats across event telemetry.

sum:totalVolume{effort:clean-and-jerk} by {week}
avg:tis{discipline:strength} by {session}
sum:sessionLoad{} where find:note{format:emom} in kg
sum:totalDistance{} .rollup(2w)
Aggregators (WQL_AGGREGATORS): sum | avg | min | max | count | last | delta
Returns: QueryResult { series[], scalar?, unit, stages }
removed

Removed: the rows: family

The rows: head was removed (simplification, tickets #1041–#1044). Every rows:… input is a parse error naming its find: replacement. runRows survives only as a legacy delegate for hand-built ASTs (RowsTable).

rows:all{scope}        → find:session{scope}
rows:<plane>{scope}   → find:session{scope, plane:<plane>}
rows:segment{…}        → find:segment{…}
rows:event{…}          → find:event{…}
find:page / source:page|pages|all → removed (type: handles page-ness)
.rollup(1d|1w)         → by {day} / by {week}

2. Lezer Grammar, AST & JavaScript Suffix Stripping

To avoid global token conflicts in Lezer (e.g. keywords shadowing word positions), WQL uses a two-phase architecture: structural Lezer parsing + JavaScript pre-parser for trailing clauses (packages/wql/src/wqlSuffix.ts, wql.ts:273-402).

Step 1Raw String
→
Step 2 (JS)Strip Pipes (| select, order by, limit)
→
Step 3 (JS)Extract Suffixes (where, window, by, .rollup, in unit)
→
Step 4 (Lezer)Parse Head + Filter Braces {…}
→
Step 5 (AST)Compose ParsedQuery Object

Boolean Algebra & Filter Value Syntax

Syntax Element Example Resolution & Semantic Rule
Comma (,) {format:for-time, domain:crossfit} AND across keys. Every filter key condition must be satisfied.
Pipe (|) {equipment:kettlebell|clubs} OR within key. Match if the field contains any of the pipe-separated alternatives.
Negate (!) {!effort:burpee} Negation spans the whole key. Rejects any row having the specified values.
Wildcard (*) {effort:back*} Trailing prefix match. Evaluated on Fact plane via startsWith (QueryService.ts:353). Note: Not evaluated on note/block content branches!
Quoted String {text:"300 Air Squats"} Multi-word literal substring matching. Quotes stripped by AST mapper.
Time Window last 8w or from 2026-01-01 to 2026-03-31 Relative (size + d|w) or civil date range (inclusive end). Relative weeks start on Monday (civilMonday).

3. Domain Entity Correlation & Cardinality Map

The persistence and query model links placements, authored markdown notes, executable AST script blocks, physical exercises, and telemetry facts:

[Page] (routing & calendar placement: /journal/2026-09-28 or /p/:slug)
  │
  ▲ (N:M via `page_notes` junction: pageId, noteId, position)
  │
[Note] (canonical authored document: UUID, title, catalog, createdAt, date)
  ├── [NoteSegment] (1:N versioned storage: raw markdown bytes)
  │
  ├── [BlockIndexRow] (1:N parsed blocks in `block_index`: wod, heading, etc.)
  │      │
  │      ▲ (N:M via `block_efforts` junction: noteId, blockContentId, effortSlug)
  │      │
  │   [Effort] (exercise definition in `efforts` registry: thruster, pull-up)
  │
  ├── [Session / Result] (1:N execution runs in `sessions`: noteId, completedAt)
  │      │
  │      └── [EventRecord] (1:N telemetry facts in `events`: noteId, blockContentId, effortSlug)
  │
  ▲ (N:M via `note_tags` junction: noteId, tagId)
  │
[Tag] (by-label unique, by-type)
  └── [TagType] (`domain`, `format`, `equipment`, `quality`, `intent`)

4. 4-Level Search Hierarchy

Every WQL query operates on one of four architectural levels:

Level Target Plane Query Head Physical Unit Primary Storage Backing
Level 1 Placement / Container find:note{source:…} / type: Route slug, calendar date, or catalog folder notes.sourceId (guides / collections) — a real page table is deferred
Level 2 Authored Document find:note Full markdown document (workout, template, guide) notes + note_tags + segments
Level 3 Executable Section find:block Fenced code block (```time, ```log, ```wod) block_index + block_efforts
Level 4 Telemetry Fact find:session|segment|event / sum: / avg: Logged metric statement or calculated aggregate events + field_catalog

7. Rows & Analytics Engine Execution Plans

A. 4-Stage Aggregate Plan (run() — QueryService.ts:992–1243)

  1. STAGE 1: SELECT (Window-First Hybrid)
    Evaluates time window. If bounded, calls getEventsByTimeRange(start, end); else scanAll() (by-metric is never used as it is non-selective). If store supports it, unions civil metric dates via getEventsByMetricDates. Flattens rows to facts via projectEventToFacts. Filters by metric key, loads note tags, and runs matchesFilters. Finally runs coverage selection (selectContributions).
  2. STAGE 2: BUCKET
    Assigns bucket keys based on time dimension: d:YYYY-MM-DD (day), w:YYYY-MM-DD (Monday of week), or N-day/N-week civil-aligned rollup windows (e.g. .rollup(2w) anchored to civil Mondays). Fills empty missing buckets across calendar domain (up to 10,000 buckets) with { value: 0, missing: true }.
  3. STAGE 3: GROUP
    Partitions series by distinct tuples of group-by dimensions (e.g. {effort, discipline}). Custom dimensions resolved off row.dimensions[key].
  4. STAGE 4: AGGREGATE & CONVERT
    Converts metric units via catalog before arithmetic. Evaluates aggregator (sum, avg, min, max, count, last, delta). Formats final series points.

B. Session & Table Execution Plans (runFindSession() / runFindTable())

Execution Mode Trigger Condition Store Read Seam Output Shape
Scoped Run Carries scope key (result:, block:, or note:) getEventsByResult(), getEventsByContent(), or getEventsForNote() RunsTable grouping runs by resultId descending by timestamp.
Cross-Workout Table find:segment{...} / find:event{...} (scope key optional) getEventsByTimeRange() or scanAll() (grain = event) Flat tabular format (TabularResult) with columns: date, effort, discipline, and numeric metrics. Supports | select, | order by, | limit, by {dim} grouping, and in kg|lb unit conversion.
