2. L2 inventory per L1 zone — groups, value types, selection effect

Selection effect is the audit's core question. Exactly two outcomes exist on mobile: the drawer KEEPS OPEN (incremental WQL edit of the current view) or CLOSES (full-query replace, direct route, or modal flow). The rule is applied per row in code via the useCloseNavigationDrawer() seam (NavigationDrawerContext.tsx) — there is no automatic pathname close.

The L2 close/keep-open rule, as implemented

Keep open — WQL edit on the current view
  • Facet accordion rows — one row per distinct value with a count; a single control cycles Off → Include → Exclude (ConditionsNavPanel.tsx:570 TRI_STATES). Edits are occurrence-exact clause edits (setFacetValueState) pushed via navigateToQuery — a new history entry per click, source scope / window / grouping / pipes survive (:127-134). Deliberately no drawer close (:222).
  • Freeform identifier rows (note / block / result id paste, :637 IDENTIFIER_FREEFORM) — same incremental edit, keep open.
Close — full-query replace, direct route, or modal
  • Landing row ("All entries" …) and user saved shortcuts — replace the whole ?q= (profile default or saved full WQL), close (:293-330).
  • Custom row — re-apply custom query, save-shortcut dialog, or clear-to-landing; all close (:297-330).
  • Create actions — modal (journal/collections) or route (playgrounds /playground, efforts /e/new); close first (:246).
  • Page actions — Feeds, Catalog crosswalk; plain routes, close (:356).
  • Everything in DashboardsNavPanel — Explorer, example WQL links, dashboard rows, New dashboard; close.
Intent, stated in code: "Full-query shortcuts … replace the whole query/page — the drawer closes after navigating. Facet edits below intentionally keep it open" (ConditionsNavPanel.tsx:218-221). The drawer also closes via the mobile-only Apply button (SidebarLayout.tsx:37 DrawerApplyFooter), Close button, Escape, and backdrop.

Row behavior invariants (all facet sections)

  • Options + counts come from the committed result set only — the panel never re-runs the query; while a fresh execution is pending the last committed rows stay visible, disabled (ConditionsNavPanel.tsx:155-165).
  • Selected values stay listed with removal controls even at zero results; zero-count unselected rows render dimmed (:581 isZero).
  • Configured expectedValues constrain/order closed vocabularies and can hide current-result values that are not in the list — selections always render and stay removable (conditionsConfig.ts header).
  • Long lists flow through the single shared sidebar scroller — no per-section viewport.

6. Findings & gaps

F1 — Static L2 children never close the mobile drawer inconsistency

NavSidebar.tsx:42-53 useNavAction runs executeNavAction with no drawer-close seam, so guide chapters, all five Settings rows, and Home's "New journal entry" leave the drawer open over the navigated page. Panel-based rows close explicitly. Per your rule these are direct routes / modal flows and should close.

Proposal — Call useCloseNavigationDrawer() in useNavAction (or L2ChildrenList's click handlers) for route/create actions, mirroring the panels.

F2 — Dead head-scope row in the source facet dead code

ConditionsNavPanel.tsx:352 passes headScope only to the source section, but conditionsConfig.ts sets source: { enabled: false } and ConditionSection returns null for disabled keys (:467) — the current query's source scope can never surface as an L2 row.

Proposal — Either re-enable a read-only scope row or delete the headScope plumbing.

F3 — Date window / Group by missing below 2xl mobile gap

streamControls renders only in the 2xl+ rail. Between lg and 2xl (desktop sidebar visible, no rail) and on all mobile, the only structured grouping/window controls are the per-route View Settings dialog (route-default grouping, not the current query's) or hand-edited WQL text.

Proposal — Publish streamControls into ActionsMenu/PageOptionsSheetRows below 2xl (entries are already nav-derived), or add a window/group section to the mobile stream sheet.
Resolved 2026-10-06. The ⋯ is now the uniform narrow-screen rendering of the L3 rail: StreamControlsNav (same date-window picker + group-by toggles) rides the shared usePageOptionsEntries model into both the header dropdown and the dock sheet below 2xl; Download Markdown moved into the rail via pageAction; the ⋯ trigger is 2xl:hidden. The dropdown primitive ignores clicks inside nested menu portals so the window picker survives inside the menu.

F4 — Stale L2 header comment: grouping presets docs drift

The ConditionsNavPanel.tsx:16 docblock still advertises "Grouping presets ('Arrange by …', 'All time')" as L2 content; grouping actually lives in L3 streamControls (2xl+) and the View Settings dialog. The panel renders no preset rows.

Proposal — Update the docblock when touching F3.

F5 — Hidden facet vocabularies by design?

source and page sections are config-disabled on every note-target stream, despite WQL_SOURCE_VALUES (journal/collections/guides/playground) and page/non-pages being valid filters. Efforts' origin and Sessions' plane remain visible.

Proposal — Confirm the disable is deliberate (source scope is injected per zone, so a source facet would fight the landing rows); if so, delete the unused expectedValues config for the two keys.

F6 — Save-shortcut dialog opens inside the drawer minor

The Custom row's save button opens SaveWqlShortcutDialog without closing the drawer (keep-open is fine for a draft dialog), but the dialog renders inside the drawer panel — on small screens it competes with the drawer chrome. Worth a glance; lowest priority.
