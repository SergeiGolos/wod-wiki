FINDING 1 · HIGH · VISUAL“Scroll panel” on every demo panel

“The literal text ‘Scroll panel’ is rendered at the bottom of every sticky demo card … It reads like a scroll-region aria-label or a dev marker leaking into the visual layer.”

What it actually is

Not a leak — a real, working control. Every tour runway section passes a segmentId, and RunwayShell wraps its caption rail in a ScrollGate: a button that toggles whether wheel/touch gestures scroll the page or the panel’s inner scroller (Scroll panel ↔ Scroll page). It is the affordance for the gesture-arbitration system documented in docs/app/screens-and-workflow.md.

The real defect

The button renders unconditionally, even when the gated rail cannot scroll. On desktop the caption rail almost never overflows, so 20+ panels carry a mute control that does nothing — which is exactly why an auditor read it as a stray label. An affordance that never applies is noise.

Change

Render the toggle only when the gated content actually overflows. Measure the inner scroller; no overflow → no button (focus-capture and Escape release keep working regardless).

// app/scroll/ScrollTrackProvider.tsx — ScrollGate
  const scrollerRef = useRef<HTMLDivElement>(null)
  const [overflowing, setOverflowing] = useState(false)
  useEffect(() => {
    const el = scrollerRef.current
    if (!el || typeof ResizeObserver === 'undefined') return
    const check = () => setOverflowing(el.scrollHeight > el.clientHeight + 1)
    const ro = new ResizeObserver(check)
    ro.observe(el)
    return () => ro.disconnect()
  }, [])

  <div className="relative min-h-0 flex-1" ref={scrollerRef}>{children}</div>
- <button type="button" className="min-h-11 self-start ..." >
-   {mode === 'captured' ? 'Scroll page' : 'Scroll panel'}
- </button>
+ {(overflowing || mode === 'captured') && (
+   <button type="button" className="min-h-11 self-start ...">
+     {mode === 'captured' ? 'Scroll page' : 'Scroll panel'}
+   </button>
+ )}

Effect: the label disappears from every non-overflowing panel on the landing page (i.e. nearly all of them, desktop and mobile), survives exactly where inner scrolling exists, and appears on capture so the release path is always visible. One component change; ScrollGate tests extend naturally with a tall-children fixture.

FINDING 2 · MEDIUM · VISUALTour callouts stuck over demo controls

“Dark tooltip bubbles (‘Run Button’, ‘Cast’) … remain visible long after their trigger moment, overlapping and partially obscuring the Run and Cast buttons.”

What it actually is

The gliding highlight ring draws a tag chip (TourRing.tsx:195) for the active stage’s target — editor.runButton→“Run Button”, timer.castButton→“Cast” (tourConstants.ts:80,83). The chip has no lifetime: it renders for the entire dwell of its stage, pinned directly over the control it names. Confirmed defect: the annotation outlives its teaching moment and sits on top of the button the visitor may want to press.

Change

Time-box the tag, not the ring. The ring keeps marking the target for the whole stage; the chip fades to 0 after ~2.5s and re-appears on hover/focus of the ring. Pure CSS on the existing chip:

/* app/tour/TourRing.tsx — tag chip */
 <span
-  className={`absolute rounded-full px-2.5 py-1 font-mono ...`}
+  className={`tour-ring-tag absolute rounded-full px-2.5 py-1 font-mono ...`}
   style={{ background: accent }}
 >{target.tag}</span>

/* index.css */
+.tour-ring-tag { animation: tag-fade 2.5s ease forwards; }
+.tour-ring-tag:hover, .tour-ring-tag:focus-within { animation: none; opacity: 1; }
+@keyframes tag-fade { 0%, 60% { opacity: 1; } 100% { opacity: 0; } }

Risk: none functional — the ring is pointer-events-none decoration over registered targets; the chip is informational. Reduced-motion users keep a static chip (@media (prefers-reduced-motion) skips the animation).

FINDING 3 · MEDIUM · VISUALDemo cards stretch to viewport height

“The mock-browser cards are sized to ~100vh regardless of content … leaving the majority of the card (and the page — ~22,600px total) as blank cream space.”

What it actually is

Half design, half defect. The pinned window is the scroll-runway dwell pattern — RunwayShell pins a calc(100dvh−65px) sticky pane while the outer track scrolls through its stages (RunwayShell.tsx:66). The window height is the point: the demo stays put while captions advance. The defect is inside it: the mock-window card is a flex child stretched by items-stretch, so short content floats in a full-height card with a dead band.

Change

Keep the dwell window; make the card hug its content and center it, instead of stretching.

// app/canvas/RunwayShell.tsx — the measured context row
- className={`... ${split ? 'flex-row items-stretch gap-[...]' : 'flex-col gap-6 ...'}`}
+ className={`... ${split ? 'flex-row items-center gap-[...]' : 'flex-col gap-6 ...'}`}

Plus in the pane hosts (TourSectionRunway screens, WQL strip): h-full → max-h-full w-full so the card’s height comes from content, capped by the window. The editor/timer demos (genuinely tall) are unchanged; the WQL strip and language demos collapse to their natural height and the dead band disappears. Page height shrinks accordingly — the 100vh tracks keep their scroll choreography, the cards stop impersonating it.

FINDING 4 · MEDIUM · UXGuide intro: display wall + false link affordances

“~9 lines of heavyweight display text, with the words ‘run’ and ‘query’ styled in link blue … they look clickable but are not.”

What it actually is

Two stacked choices amplify each other. The chapter intro is prose set at display weight, and its **run**/**query** emphasis renders bold and ink-blue — the same visual token real links use. On the homepage, section headings do it deliberately with accent-colored fragments (TourCaptions.tsx:173: <em class="not-italic" style="color: accent">). Reusing the accent for non-interactive fragments trains false affordance everywhere the pattern appears.

Change

Two-part, one rule: blue means clickable, nothing else. (a) In canvas prose styling, strong in chapter intros drops to ink + weight only; (b) the homepage’s colored heading fragments switch from accent-blue to the section’s non-link accent treatment (italic serif or muted ink), so each accent color stays a section marker, not a link cue:

// app/tour/TourCaptions.tsx
-<em className="not-italic" style={{ color: TOUR_ACCENTS.timer }}>The script becomes the clock.</em>
+<em className="font-serif italic text-foreground/80">The script becomes the clock.</em>

And cap the guide intro: first paragraph of a chapter renders at body scale/weight (it already is body prose — the display treatment comes from the chapter header slot in GuideRunwayGroups), max ~3 lines before the first section anchor. Blue survives only on actual <a>s.

FINDING 5 · MEDIUM · CONTENTRaw slug titles in Feeds & Collections

“‘Half Ironman 70 3 Building’ (missing the ‘70.3’ punctuation), ‘International Im Preparation’ … ‘Jerk Technique And Endurance’.”

What it actually is

Content debt, not code debt — and the escape hatch already exists. Collection member names are the humanized filename; markdown/collections/README.md:29: “Optional overrides: title: (when the filename humanizes poorly)”. swimming-post-college/ members (international-im-preparation.md, …) ship without that override, so ALL-CAPS slugs and mangled punctuation reach the UI.

Change

Primary: add title: frontmatter to the offenders (a sweep, not code):

markdown/collections/swimming-post-college/international-im-preparation.md
+---
+title: International IM Preparation
+---

Secondary (small code win): the humanizer that title-cases filenames should lowercase stop-words (and, of, for) and leave digit-dot-digit intact (70-3 → 70.3, not 70 3). That fixes the long tail of feeds titles without touching identity — ids stay path-derived.

FINDING 6 · MEDIUM · VISUALCollection detail: dead space + truncated TOC

“The main column ends after four workout rows (~390px) while the viewport continues … TOC truncates entries as ‘national-qualifier-distance-fr…’.”

What it actually is

Both ends of the same page. The TOC rail clips labels with a hard single-line truncate (app/nav/MenuList.tsx:127) — with slug-derived labels (Finding 5) the ellipsis fires constantly. The main column inherits a min-height from the two-column shell, so a 4-item collection leaves ~75% cream.

Change

// app/nav/MenuList.tsx
-<span className="min-w-0 flex-1 truncate" title={entry.label}>{entry.label}</span>
+<span className="min-w-0 flex-1 line-clamp-2 break-words">{entry.label}</span>

Wrapping beats ellipsis for navigation targets: with Finding 5’s human titles most labels fit one line anyway, and the rare long one wraps instead of hiding its destination. For the dead space: let the footer follow the content column (drop the forced min-height on sparse collections) and, when a collection has <8 members, surface the “related collections” rail (same domain tag) below the rows — the data is already in the catalog index.

FINDING 7 · LOW · CONTENT“Avg TIS 620.447”

“Three decimal places on a large display number. Compare ‘Adherence 0.938’, which legitimately needs three decimals.”

What it actually is

QueryValue prints the raw scalar with toLocaleString() — full float precision, whatever the magnitude (packages/ui/src/widgets/QueryValue.tsx:36). Every dashboard value widget shares this, so the fix lands once.

Change

Significant digits, not fixed decimals — large numbers round, small ratios keep precision:

// packages/ui/src/widgets/QueryValue.tsx
-          {value.toLocaleString()}
+          {value.toLocaleString(undefined, { maximumSignificantDigits: 3 })}

620.447… → 620; 0.938 → 0.938; 36,200 → 36,200. One line; the existing widget test (widgets.test.tsx §2) gains a precision case.

FINDING 9 · LOW · A11YEmail input: label & feedback

“The email field communicates only via placeholder … no <label> and no visible success/error state.”

Correction

Half right. There is no visible label, but the input carries aria-label="Email address" (OfferingTiers.tsx:98) — the accessibility tree is fine; what’s missing is the persistent visible label and any submit feedback. Placeholder-as-label fails the moment someone types (the hint vanishes), so the visible label is still worth adding.

Change

<form onSubmit={...} className="...">
+ <label htmlFor="interest-email" className="sr-only sm:not-sr-only text-xs text-muted-foreground">
+   Email address
+ </label>
  <input id="interest-email" required placeholder="you@example.com" ... />

Plus a submitted state: on success, swap the form for Noted — we’ll email you when hosted plans open. (the interest endpoint already resolves; the component just never showed it). Keep the aria-label; the visible label supersedes it harmlessly.

FINDING 10 · LOW · VISUALMobile FAB overlaps hero controls

“The blue circular search FAB renders over the hero mockup’s bottom-right control cluster (share/expand) and follows scroll.”

What it actually is

SearchFab is the thumb-dock circle; ResponsiveActions owns its corner positioning, safe-area clearance, and keyboard lift. It overlays page content by design — the defect is only that the hero mockup parks its share/expand cluster in the same corner.

Change

Move the collision, not the FAB: the hero mockup’s control cluster shifts left of the FAB zone (pr-16 on that corner cluster at mobile widths), and the FAB gains mix-blend-mode-safe scrim only when a fullscreen timer overlay is open (it already hides under overlays via the dock). One media-scoped padding rule in the hero card — cheaper and more predictable than scroll-linked FAB hiding.

FINDING 11 · LOW · VISUAL“3 result s captured”

“The chip caption wraps as ‘3 result / s captured’, splitting the word ‘results’.”

What it actually is

A JSX pluralization that emits separate text nodes — {outputCount} result{outputCount !== 1 ? "s" : ""} captured (RuntimeTimerPanel.tsx:169). Browsers may break lines between inline text nodes, so narrow widths split exactly between result and s.

Change

// src/components/organisms/editor/RuntimeTimerPanel.tsx
-  <span>
-    {outputCount} result{outputCount !== 1 ? "s" : ""} captured
-  </span>
+  <span className="whitespace-nowrap">
+    {`${outputCount} ${outputCount !== 1 ? 'results' : 'result'} captured`}
+  </span>

Single text node + whitespace-nowrap: the chip can still wrap before “captured” if truly starved, but never inside the word. The adjacent timestamp span already carries its own node.

Suggested order

  • Ship-today one-liners: F7 (precision), F11 (nowrap), F8 (copy) — three lines total, zero risk.
  • Same afternoon: F1 (gate visibility — kills the High finding’s symptom), F2 (tag fade), F9 (label + submitted state).
  • Design pass: F3 (card hug) and F4 (blue-means-link rule) together — both are the same “intentional vs implied” cleanup of the runway pattern.
  • Content sweep: F5 titles, F6 TOC wrap — F6’s fix gets cheaper after F5.
  • Mobile polish: F10 with the next hero-card touch.

The meta-finding: the audit’s strongest claims (“dev marker leaking”) were the ones where the site has an intentional system the auditor couldn’t see from the outside. The fix in both cases (F1, F3) is not to remove the system but to stop rendering its affordances where they don’t apply.
