Header query bar — the composer moves up

Stitch redesign for the query-page family (QueriableStreamView profiles: Journal / Collections / Feeds / Library / Efforts / Results). Today the composer is a tall card under the page title. The redesign collapses it into the sticky header: a data-type selector drives the WQL head clause, the composed query reads as one quiet mono line, and every overflow detail opens in a dialog embedding the same composer as the ⌘K command palette.

RULE 1 Composer in the header

One sticky ~56px line: title → data-type pill → query chips → ⌘K / view / new. No composer card in the content area. The old source-scope radio row is absorbed by the type selector.

RULE 2 Type drives the query

The selector states the expected result type and pivots the head clause: find:note find:block find:effort rows:… sum:…. Scope filtering (journal/collections/feeds) becomes a filter clause again, crafted in the dialog.

RULE 3 Overflow hides, palette crafts

Chips that don't fit collapse behind a +N chip. It (and the ⌘K button, and tapping the bar on mobile) opens the palette-composer dialog — segmented type row, pills, live stage counts, Apply writes back to ?q=.

Header Query Bar — interactive

One page, all states: switch the data type (notes → sessions → efforts), watch the WQL re-base, remove chips inline, overflow the bar, then open the edit dialog (⌘K). Resize under 640px — the dialog becomes the bottom sheet.

IMPLEMENTATION MAP (WHEN THIS LANDS IN THE APP)

  • StickyPageHeader grows a queryBar slot rendering left-to-right: title, QueryTypeSelect, QueryChipRow (measured overflow → +N), actions.
  • QueryTypeSelect maps stream profile → WQL head via the existing pivotSourceQuery / pivotPills seam; scope profiles (journal/collections/feeds) re-base the source: clause instead of hiding it.
  • The dialog is PaletteShell in WQL mode seeded with the page query (usePaletteStore.open({ wql: { initialQuery: q, execute } })) plus an Apply action; no second composer implementation.
  • SourceScopeRadio and the subheader composer block retire; view settings (sliders) stays a header action.
